# Release 4.0.1

**Release Date:** 2026-10-22

Taihei Framework lorem 4.0.1 is a bug-fix release for the random generators in `LoremIpsum`. Before this release, `int(bound)` and `long(bound)` never returned `bound` and returned 1 twice as often as any other value. The generators built on them inherited the bias:

- `language` could never pick the first language.
- `times` never produced `bound` items.
- `localDate` never produced December, the 28th or the year 3000.
- Zip codes and phone numbers never contained the digits 0 or 9.

All of these now draw uniformly from their documented ranges. Generated e-mail addresses and URLs now use the reserved `.example` top-level domain (RFC 2606), so test data can never reach a real host or mailbox.

The release is binary-compatible with 4.0.0. It also adds Scaladoc to the whole public API and marks the word-list internals as internal. On the project side it corrects the licence history in NOTICE, adds contributor documentation and hardens the release process, including the MiMa binary-compatibility check.

## Highlights

- **Uniform random numbers**: `int(bound)` and `long(bound)` now return every value in `[1, bound]` with equal probability, `bound` included.
- **Every value reachable**: `language`, `times`, `localDate`, `zipCode`, `phone`, `address`, `futureDate` and `pastDate` now cover their full documented ranges.
- **Safe e-mail and URL domains**: every generated domain ends in `.example`, so a generated address or URL never resolves to a real site or mailbox.
- **Documented API**: every public member of `LoremIpsum` and `SampleImages` now has Scaladoc that states its range and shape.
- **Reliable binary-compatibility checks**: MiMa now always compares a release with the release before it, and a patch or minor release cannot skip that check unnoticed.

## Changelog

### Added
- Scaladoc for `LoremIpsum` and `SampleImages`, covering ranges, randomness, the non-random `today`/`yesterday`/`tomorrow`, and the `IllegalArgumentException` thrown for a non-positive `bound`.
- Scaladoc that marks `ResourceLoader`, `SampleWordCollection` and the objects in `dev.taihei.lorem.sources` as internal. They are not covered by the compatibility promise and will become private in the next major release; use `LoremIpsum` instead.
- `CONTRIBUTING.md`, covering the build (`make validate`), how to submit a change, the Developer Certificate of Origin sign-off and how to report a security issue.
- Tests that check full range coverage and uniformity:
  - `int` and `long` reach `bound`.
  - `int(2)` is balanced between 1 and 2.
  - `language` reaches every language.
  - `times` returns up to `bound` items.
  - Zip codes and phone numbers use all ten digits.
  - `localDate` reaches December and the 28th.
  - E-mail addresses and URLs use only `.example`.
  - `name` has the expected structure.
- README coordinates for sbt on the JVM (`%%`), alongside the existing Scala.js (`%%%`) line.

### Changed
- `DomainNames` now lists only `.example` domains, for example `brightwavehub.example` instead of `brightwavehub.com`. This changes the output of `email` and `url`.
- `bool` now uses `SecureRandom.nextBoolean()`, so true and false are exactly equally likely.
- The Claude Code skill in `docs/skill/` is renamed from `library-genius-lorem` to `taihei-lorem`, and its documentation now matches the corrected generator behaviour. The GitHub workflow and the `scripts/sync-skill-docs.sh` script that pushed the skill to an external marketplace are removed. The skill is now copied by hand into a plugin or a project's `.claude/skills/`.
- NOTICE and the README licence section now record the full licence history:
  - 1.0.0–1.1.0: GPL-3.0
  - 2.0.0: MIT
  - 3.0.0: Apache 2.0, as `edo-lorem`
  - 4.0.0 and later: Apache 2.0, as `taihei-lorem`

  NOTICE also states that the code of the earlier versions was relicensed under the Apache License 2.0 by its sole copyright holder.
- Release tooling (`Makefile`):
  - Release state is now kept in the repository as a gitignored file, instead of at a predictable path in `/tmp`.
  - Release state and release notes are written atomically, and a release refuses to use a state or notes file that is tracked by git or is a symlink.
  - `release-finalize` refuses a version that is already tagged or is not the next version after the current one.
  - `release-abort` validates the version it reads.
  - Release notes are generated by a `claude` call with no tools and no user settings; it receives `build.mill` and the diff directly.

### Fixed
- `int(bound)` and `long(bound)` never returned `bound` and returned 1 twice as often as any other value. They now return a uniform value in `[1, bound]`.
- `language` never returned the first language in `Language.values`.
- `times(bound, f)` never produced `bound` items, so neither did `paragraph`, `paragraphs`, `words`, `sentence`, `sentences`, `title`, `street` or `htmlParagraphs`.
- `localDate` never produced December, the 28th of a month or the year 3000.
- `zipCode` and `phone` used only the digits 1–8. They now use 0–9.
- The house number in `address` never reached 100, and `futureDate`/`pastDate` never reached 1000 weeks.
- MiMa baseline (`build.mill`): on a tagged release commit, MiMa compared the release with itself. Before Maven Central had synced the new artifact, that comparison could also fail to resolve. MiMa now compares with the previous tag.
- Unexpected git errors while looking for the MiMa baseline, such as a shallow clone, are now shown instead of silently leaving MiMa without a baseline.
- `release-prepare` now refuses a patch or minor release whose MiMa baseline is not the current version.

## Module Changes

- `lorem.jvm` (`dev.taihei:taihei-lorem_3`): behaviour fixes in `LoremIpsum` and `DomainNames`, Scaladoc throughout, and the internal marker on `ResourceLoader`.
- `lorem.js` (`dev.taihei:taihei-lorem_sjs1_3`): the same changes, including the JS `ResourceLoader`.
- Shared test suite (`LoremIpsumSpec`): new tests for range coverage, uniformity and the `.example` domains, run on both platforms.
- Build and release (`build.mill`, `Makefile`): MiMa baseline selection and release-process hardening.
- Documentation: README, NOTICE, the new CONTRIBUTING.md and the `docs/skill/` skill.

4.0.1 is binary-compatible with 4.0.0, as checked by MiMa. No public signatures changed, but some generated values did:

- `email` and `url` now end in `.example`.
- `int`, `long` and the generators built on them can now return their upper bounds.
- Zip codes and phone numbers can now contain 0 and 9.
- `localDate` can now fall in December and on the 28th, and `times(bound, f)` can return `bound` items.

**Check your own use of `int` as an index.** `int(n)` can now return `n`, as documented. Code such as
`xs(LoremIpsum.int(xs.length))` will now throw `IndexOutOfBoundsException` now and then; before, it
silently never picked the first element. Use `xs(LoremIpsum.int(xs.length) - 1)` instead.

Tests that assumed the old, narrower ranges, or that count the words of `name`, may need to be updated. A last name can contain spaces, as in "De La Cruz".
